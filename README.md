# Sarhad

A one-minute daily puzzle: you get two Indian states and join them by land, naming the states and union territories in between in any order. Faster wins score more. Everyone gets the same pair each day (Asia/Kolkata date). Practice gives you a random pair at any time and works offline.

React 19 + Vite + Tailwind PWA on Vercel; Supabase (Postgres, anonymous auth, one Edge Function) for the daily and the leaderboard.

- Spec: [`docs/DESIGN.md`](docs/DESIGN.md) · Visual system: [`docs/DESIGN-SYSTEM.md`](docs/DESIGN-SYSTEM.md)
- Data: [`data/SOURCES.md`](data/SOURCES.md) · Border rulings: [`data/ADJACENCY_NOTES.md`](data/ADJACENCY_NOTES.md)

## Run it

Requires Node 22+ and npm. The Supabase CLI runs through `npx`, and a local backend needs Docker.

```sh
git clone https://github.com/nitya2405/sarhad.git
cd sarhad
npm ci
npm run dev:offline        # http://localhost:5173 — no server, bundled schedule
```

`dev:offline` ignores `.env` completely: no sign-in and no network, and the daily comes from the bundled `src/data/daily.json`. Use it for UI work.

With npm 11, `npm ci` may warn that the install scripts of `better-sqlite3` and `msgpackr-extract` were skipped. Both are optional native parts of `mapshaper` (GeoPackage support and a msgpack speed-up), which this project doesn't use. You can ignore the warning.

### With a backend

Use a local Supabase while developing. Plain `npm run dev` against the hosted project creates a real anonymous user on every fresh browser.

Docker (Docker Desktop on Windows and macOS) must be running. The first `supabase start` downloads the Supabase images, a few GB, and takes several minutes.

```sh
npx supabase start -x logflare,vector     # local stack in Docker; applies supabase/migrations
npx supabase status -o env                # prints API_URL=… and PUBLISHABLE_KEY=… among others
cp .env.example .env
#   VITE_SUPABASE_URL      = the API_URL value       (http://127.0.0.1:54321)
#   VITE_SUPABASE_ANON_KEY = the PUBLISHABLE_KEY value (sb_publishable_…)
npm run dev
npx supabase functions serve finish-daily --no-verify-jwt   # in a second terminal
npx supabase stop                         # when you're done
```

Locally it's fine to play the daily through to the end: it writes only to your local database.

## Environment variables

| Name | Where | Notes |
| --- | --- | --- |
| `VITE_SUPABASE_URL` | `.env`, Vercel | `https://<ref>.supabase.co` |
| `VITE_SUPABASE_ANON_KEY` | `.env`, Vercel | the **publishable** key (`sb_publishable_…`); safe in the browser |
| `SARHAD_SECRET_KEY` | Supabase function secret | secret key (`sb_secret_…`) used by `finish-daily`; set with `supabase secrets set`, never in `.env` for the app |
| `SUPABASE_DB_PASSWORD` | your shell only | optional, read by `supabase db push` |
| `SUPABASE_PUBLISHABLE_KEY` | GitHub Actions secret | for the keepalive job |

Only `VITE_*` values reach the browser. `.env` and `.env.*` are git-ignored, except `.env.example`.

When both `VITE_*` values are set, the build is a **server build**. When they're missing, or with `--mode offline`, it's an **offline build**. On Vercel, a production build without both values fails on purpose, because it would ship the schedule.

## Architecture

```
supabase/functions/_shared/engine/   pure TypeScript game rules — imported by BOTH the app (@engine) and the Edge Function
  resolve.ts   typed text → region (aliases, Hindi, typo distance, live suggestion)
  graph.ts     linked set, win check, shortest routes, graph validation
  score.ts     par, points, board order        replay.ts  re-plays a guess list (server-side check)
  time.ts      IST dates                       streak.ts  streaks from attempts
src/                                 the app
  App.tsx, screens/, components/       Home → Ready → Game → Result
  game/        local model, localStorage (sarhad:v1), server sync with retry
  lib/server.ts  supabase-js, loaded after first paint
  data/*.json  generated by scripts/ (map, regions, adjacency, puzzles, daily)
supabase/
  migrations/  tables + RLS + RPCs (init), generated daily schedule, anon board grant
  functions/finish-daily/  verifies the caller, replays the guesses with the shared engine, scores with server time
  tests/       pgTAP (P1–P7)
```

**Offline vs server builds.** An offline build bundles the year's schedule and runs the daily entirely on the device. A server build ships **no schedule**: the daily pair comes only from `start_daily()` when the player presses Start, and the `daily_schedule` table is readable only for past dates, so future pairs can't be read from the bundle or the API. A build check (`sarhad:no-future-dates` in `vite.config.ts`) fails a server build that contains any date after today in IST. Practice uses the bundled puzzle pool in both builds.

**Daily flow (server).**
1. On first open the app signs in anonymously, after the first paint.
2. Start calls `start_daily()`, which records the server start time; calling it again returns the same row.
3. You play locally.
4. `finish-daily` replays the guesses with the same engine the app uses, then commits through `finish_daily_commit` (service role only, written once). Time is server finish minus server start.
5. `get_daily_board(date)` returns the top 50 with display names only.

If the network fails, the local result stays and retries with backoff.

## Tests

Once per machine, install the browser Playwright uses. `test:e2e` and `npm run icons` need it:

```sh
npx playwright install chromium
```

```sh
npm run typecheck
npm run test:unit          # Vitest: engine, model, storage, labels, App (offline + server, server mocked)
npm run test:e2e           # Playwright (Chromium, offline build on :4173); screenshots → test-results/screens/
npx vitest run -c supabase/scripts/vitest.finish-daily.config.ts   # Edge Function handler
npx supabase test db --local                                       # pgTAP P1–P7 (needs `supabase start`)
npm test                   # unit + e2e
```

## Data scripts

The raw GeoJSON (`data/raw/`, ~2.9 MB) is only processed by scripts:

```sh
npm run data:build     # all of the below, in order
npm run data:map       # GeoJSON → simplified, projected src/data/map.json + minimap.json
npm run data:check     # cross-checks the hand-curated border graph against the geometry
npm run data:validate  # graph checks (symmetry, connectivity, playable set)
npm run data:puzzles   # puzzle pool + daily schedule (fixed seed; past dates never change)
npm run data:sync      # app and Edge Function copies of the data match
npm run db:schedule    # regenerates the schedule seed migration from src/data/daily.json
```

The border graph `data/adjacency.v1.json` is curated by hand. The map is only a cross-check (see `ADJACENCY_NOTES.md`).

The scripts are deterministic: on an unchanged checkout, `data:build` and `db:schedule` reproduce the committed files exactly, so `git diff` stays empty. On Windows, `git status` may still list the regenerated JSON files as modified. That's only line endings: Git checks the files out with CRLF and the scripts write LF, and `git add` normalises them back.

Generated assets (commit the output):

```sh
npm run icons          # app icon + favicon + PWA PNGs (public/), rendered with Playwright's Chromium
npm run font:wordmark  # Silkscreen subset for the wordmark; needs Python with fontTools and brotli:
                       #   pip install fonttools brotli
```

## Deploy

- **Supabase:**
  - `npx supabase link --project-ref <ref>`
  - `npx supabase db push`
  - `npx supabase secrets set --env-file supabase/.env.secrets`, where the file holds `SARHAD_SECRET_KEY=…`
  - `npx supabase functions deploy finish-daily --no-verify-jwt`; the function checks the caller's token itself.
  - In the dashboard, enable anonymous sign-ins.
- **Vercel:**
  - Import the repo; `vercel.json` sets the Vite build, the SPA rewrite and cache headers.
  - Set `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY` for Production (and Preview if previews should use the server).
- **Keepalive:** add the `SUPABASE_PUBLISHABLE_KEY` repository secret. `.github/workflows/keepalive.yml` reads the board once a day so the free project doesn't pause.

## Known limits

- The map file predates the 2014 Khammam transfer. **AP–CG** (kept) and **OD–TG** (excluded) follow the post-2014 borders and still need confirming on the official political map.
- Not yet checked on real devices: Android vibration, on-screen keyboard behaviour, screen readers.
- The schedule covers 2026-10-15 to 2027-10-14 and must be extended (append only) before it runs out.
- The puzzle pool has routes of 2–5 regions; there are none of 6.
- GitHub turns off scheduled workflows after 60 days without repository activity, so check that the keepalive is still running.
- **Fast finishes:** a daily won faster than 1.5 s + 1 s per guess is stored and scored but flagged (`daily_attempts.flagged`) and kept off the public board; the player sees it as "under review". Nothing reviews or clears flags yet.
- **Anonymous data:** a player is an anonymous session in localStorage, with no email or other link. Clearing browser data starts a new player, and their old server rows stay orphaned.
  - After the first finished game the app asks for persistent storage (`navigator.storage.persist()`).
  - iOS Safari players see an "Add to Home Screen" tip, because Safari deletes a site's storage after 7 days without a visit.
- English UI only. GPS, state leaderboards, streak freezes and notifications are out of scope.
